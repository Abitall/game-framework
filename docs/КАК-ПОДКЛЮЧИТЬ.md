# Как подключить фреймворк

Три сценария: пустая папка, существующий проект, перенос игры на другой движок.

---

## 1. Новый проект в пустой папке

### Вариант A — клонировать шаблон и обнулить историю (рекомендую)

```powershell
cd "C:\Phaser Projects"
git clone https://github.com/Abitall/game-framework.git MyGame
cd MyGame
Remove-Item .git -Recurse -Force
git init -b main
npm install
```

Почему обнулять: в шаблоне 320 коммитов истории фреймворка. Новому проекту они
не нужны и мешают читать `git log`.

### Вариант B — через GitHub Template

Если репозиторий помечен как шаблон:

```powershell
gh repo create MyGame --template Abitall/game-framework --private --clone
cd MyGame
npm install
```

### Дальше

```powershell
opencode
```

В сессии — `/start`. Он спросит идею, движок и команду, поставит `engine-*`
модуль и создаст каталоги.

### Оставить связь с шаблоном

Чтобы потом забирать улучшения фреймворка:

```powershell
git remote add framework https://github.com/Abitall/game-framework.git
git fetch framework
```

Это не автоматическое обновление — вы вручную смотрите, что изменилось, и
переносите нужное. Так безопаснее: правки в вашем проекте никто не тронет.

## 2. Существующий проект (Unity, Godot, что угодно)

### Куда класть

**В корень проекта, рядом с `Assets/`, а не внутрь него.**

```text
MyUnityGame/
├── Assets/              ← Unity, не трогаем
├── ProjectSettings/     ← Unity
├── Packages/            ← Unity
├── Library/             ← Unity, генерируется, агент не читает
├── .framework/          ← фреймворк
├── .opencode/           ← активные модули
├── AGENTS.md
├── opencode.json        ← объединить с существующим, если есть
├── docs/agents/
├── docs/framework/
├── production/
├── design/
└── tools/
```

**Почему не в `Assets/`:** Unity импортирует всё, что там лежит. 900 markdown-
файлов фреймворка превратятся в 900 ассетов и 900 `.meta`-файлов, замедлят
импорт и забьют проект. Всё, что вне `Assets/`, для Unity невидимо — это то,
что нужно.

### Что копировать

| Копировать | Зачем |
|---|---|
| `.framework/` | библиотека агентов, скиллов, модулей |
| `.opencode/` | активные модули, плагины, установщик |
| `AGENTS.md` | правила проекта |
| `opencode.json` | **объединить**, не перезаписывать |
| `docs/agents/` | конфигурация по темам |
| `docs/framework/` | шаблоны документов, справочники |
| `production/PIPELINE.md`, `production/SCOPE.md` | гейты и контракт |
| `tools/*.mjs` | инструменты: гейты, скоуп, поиск, ComfyUI, Obsidian |

| Не копировать | Почему |
|---|---|
| `.git/` | у проекта своя история |
| `tests/`, `skill-testing-framework/` | это тесты самого фреймворка, не игры |
| `.github/` | CI шаблона вам не нужен |
| `src/`, `assets/`, `design/` | у проекта свои; создайте пустые, если нет |

Команда копирования без `.git` и без тестов:

```powershell
$src = "C:\Phaser Projects\game-framework"
$dst = "C:\Phaser Projects\MyUnityGame"

foreach ($item in ".framework", ".opencode", "docs", "production", "tools") {
  robocopy "$src\$item" "$dst\$item" /E /XD ".git" "node_modules" /NFL /NDL /NJH /NJS
}
Copy-Item "$src\AGENTS.md" $dst -Force
```

`docs` копируется целиком: там же шаблоны и русские переводы.

### Если `opencode.json` уже есть

Не перезаписывайте. Объедините вручную:

- `plugins` — добавьте три пути из шаблона;
- `mcp.servers` — добавьте `websearch`, `comfyui`, `aseprite` (и `unity`, если
  ставите Unity MCP);
- `permissions` — перенесите правила, особенно запреты на `rm -rf`, force push,
  `.env`;
- `instructions` — список файлов `docs/agents/*.md`.

### Если `package.json` уже есть

Скопируйте только блок `scripts` из шаблона, не заменяя существующие скрипты.
Для Unity проекта `package.json` может не быть вовсе — тогда копируйте целиком,
он нужен инструментам и git-хукам.

### Защитить агента от мусора Unity

В `opencode.json` добавьте запреты на чтение тяжёлых каталогов:

```json
{ "action": "read", "resource": "Library/**", "effect": "deny" },
{ "action": "read", "resource": "Temp/**", "effect": "deny" },
{ "action": "read", "resource": "Logs/**", "effect": "deny" },
{ "action": "read", "resource": "obj/**", "effect": "deny" },
{ "action": "read", "resource": "Build/**", "effect": "deny" },
{ "action": "read", "resource": "Builds/**", "effect": "deny" },
{ "action": "read", "resource": "node_modules/**", "effect": "deny" }
```

Без этого агент однажды сделает `Glob Library/**` и утонет в бинарниках.

### `.gitignore`

Добавьте к существующему (Unity-часть обычно уже есть):

```gitignore
# framework runtime
production/images/
production/shutdown.json
dist-play/
node_modules/
```

`.opencode/` **не игнорируйте** — это конфигурация проекта, она должна быть в git.

### Дальше

```powershell
opencode
```

В сессии:

```text
/adopt              # аудит существующих артефактов и план миграции
```

И поставьте модуль движка:

```bash
node .framework/install.mjs add engine-unity
```

Он принесёт 5 Unity-специалистов и документацию по Unity 6.3 LTS.

## 3. Перенос игры с одного движка на другой (Unity → Phaser)

Главное правило: **переносим поведение, а не код.** Построчный перевод C# в
TypeScript даёт второй плохой проект вместо одного хорошего.

### Шаг 1. Заморозить эталон

Соберите текущую версию и сохраните как эталон для сравнения:

```bash
npm run publish:play        # или соберите Unity-билд
```

Старая игра становится спецификацией: что должно получиться.

### Шаг 2. Вытащить дизайн из кода

```text
/reverse-document Assets/Scripts/
```

Читает код и пишет GDD в `design/gdd/`: механики, формулы, константы, краевые
случаи. Это то, что вы переносите. Код — нет.

Отдельно выпишите:

- **формулы** — урон, очки, прогрессия;
- **константы** — все числа из кода;
- **состояния** — что происходит с игроком и миром;
- **данные** — уровни, таблицы, конфиги.

### Шаг 3. Разделить движковое и общее

| Живёт в новом проекте | Выбрасывается |
|---|---|
| правила, формулы, баланс | MonoBehaviour-жизненный цикл |
| данные уровней и конфиги | префабы и сцены Unity |
| ввод как намерения (вперёд, прыжок) | прямой опрос клавиш |
| рендеринг как следствие состояния | логика, зашитая в `Update` |

Правило, которое уже есть в фреймворке: `src/systems/**` не импортирует движок.
Это делает перенос возможным — системы не знают, кто их рисует.

### Шаг 4. Архитектура под новый движок

```text
/create-architecture
/architecture-decision "перенос Unity → Phaser: сцены и системы"
```

Зафиксируйте в ADR: что переносится как есть, что переписывается, что
выбрасывается. Через полгода вы забудете, почему решили именно так.

### Шаг 5. Порядок переноса

1. **Данные** — конфиги, уровни, таблицы. Их можно проверить без кода.
2. **Системы** — по одной, с тестами на формулы. Они движко-независимы.
3. **Ввод** — намерения, не клавиши.
4. **Рендеринг** — здесь всё новое, но системы уже работают.
5. **Интерфейс** — последним, когда есть что показывать.

Не начинайте с рендеринга. Соблазн велик, но пока нет систем, рисовать нечего.

### Шаг 6. Считать паритет, а не «готово»

Заведите контракт в `production/SCOPE.md`:

```markdown
## Contract
- [ ] механик перенесено: 12 — count: fs.readdirSync('src/systems').length
- [ ] уровней перенесено: 8 — count: fs.existsSync('assets/levels') ? fs.readdirSync('assets/levels').length : 0
```

`node tools/scope.mjs` покажет разрыв. «Готово» становится числом, а не
ощущением.

### Шаг 7. Сравнивать бок о бок

Два хоста уже настроены: старая игра на одном экране, новая на другом.
`/gauntlet` сравнивает кадры слепым методом — вы не знаете, где чей, пока не
напишете вердикт.

## 4. Что агенту можно читать

| Читать | Не читать |
|---|---|
| `src/`, `assets/`, `design/`, `docs/`, `production/` | `Library/`, `Temp/`, `Logs/` (Unity) |
| конфиги, GDD, ADR | `node_modules/`, `dist/`, `build/` |
| код проекта и тесты | `.git/`, `obj/`, `Builds/` |

Правило простое: если каталог генерируется или весит гигабайты — закрыть
чтение в `opencode.json`. Это экономит не только токены, но и время: поиск по
`Library/` занимает минуты и ничего не находит.
