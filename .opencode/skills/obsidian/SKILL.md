The vault is the user's thinking space: ideas, concepts, plans, open questions.
It is written **in Russian**, because only the user reads it. The project itself
stays in English.

The vault is a plain folder of markdown. Obsidian indexes it on its own, so no
plugin or server is involved.

## The shape of a readable graph

A vault that grows for weeks becomes a ball of string: every note links to every
neighbour, five hub cards link to everything, and the graph view stops being a
map. The fix is a fixed shape, three levels, no more:

```
заметка  →  Сфера  →  Карта по типу
```

- **Заметка** has exactly one `sphere` in its frontmatter. That is its home.
- **Сфера** (`50 Карты/Сфера — <название>.md`) is generated from that field: the
  list of notes belonging to one area of the game.
- **Карта по типу** (`50 Карты/Карта — <тип>.md`) is generated from `type`.

Both cards are generated by `index`; neither is edited by hand. A note links to
its neighbours by meaning, not to the cards — the cards already contain it.

Rules that keep the picture legible:

- **One sphere per note, always.** A note without a sphere is a loose dot in the
  graph.
- **Two to four links per note.** More than six makes the note a hub; hubs belong
  in a card, not in prose.
- **Link up, not sideways.** The sphere card is how a note is found; do not
  reproduce the card's list inside a note.
- **Tags are for searching, links are for the graph.** A vague connection is a
  tag, not a link.
- **One link per pair.** Two links to the same note draw one edge and add noise.
- **Titles are the link targets**, so they must stay short, unique and stable.
  Renaming a note breaks every link to it.

## Phase 1: Find the vault

```bash
node tools/obsidian.mjs vault
```

Resolution order: `--vault`, `OBSIDIAN_VAULT`, `production/obsidian.json`.
Never guess the path and never write outside it.

If the folder is missing, ask before creating it — the user may have moved the
vault. Then `node tools/obsidian.mjs init` creates the folder structure and the
templates.

## Phase 2: Search before creating

```bash
node tools/obsidian.mjs search "<ключевые слова>"
```

If a similar note exists, **link to it instead of creating a duplicate**. Two
notes about the same idea are worse than one imperfect note: in the graph they
look like two ideas.

Search both title and body; the command does both.

## Phase 3: Choose the sphere before writing

The sphere is the first thing to decide, because it decides where the note lives
in the user's head. It comes from the game, not from the folder structure:
`экономика`, `бой`, `повествование`, `интерфейс`, `арт`, `процесс`.

- Ask the user if there are two plausible spheres. One extra question beats a
  note filed in the wrong place.
- A new sphere is a decision about the project's structure, so name it in the
  user's words, not in invented terminology.
- If the note belongs to no sphere yet, put it in `00 Входящие` with
  `sphere:` empty and say so — an inbox note is honest, a misfiled one is not.

## Phase 4: Create the note

```bash
node tools/obsidian.mjs new идея "Короткое название"
```

Types: `идея`, `концепт`, `план`, `документ`, `вопрос`. The command refuses a
duplicate title, which is what you want.

Fill the body from the conversation. One note = one thought. If you are writing
"and also", that is a second note. Fill `sphere:` in the frontmatter — the
template leaves it empty on purpose.

## Phase 5: Link up and index

Replace the empty `[[ ]]` in **Связи** with **two to four real links** to notes
that genuinely relate, then:

```bash
node tools/obsidian.mjs index
```

That rebuilds every `Карта — <тип>.md` and `Сфера — <сфера>.md`. Those files are
generated; never edit them by hand.

## Phase 6: Report

One short block: note title, sphere, the links you added. Nothing else.

## Note format

```markdown
---
type: идея
status: черновик
project: AfterLife
sphere: экономика
created: 2026-11-21
tags: [механика, каскад]
---

# Короткое название

Суть в двух-трёх предложениях.

## Связи

- [[Как устроено]]
- [[Сфера — экономика]]
```

Keys stay Latin (`type`, `status`, `sphere`, `tags`) because Obsidian and future
queries read them; values and all prose are Russian.

## Rules

- **Russian only.** Titles, body, tags, statuses.
- **One note, one thought, one sphere.**
- **Titles are link targets.** Short, unique, no `:`, `/`, `\`, `?`, `*`, `"`,
  `<`, `>`, `|`. The command strips them, but a clean title is better.
- **Never edit a note you did not create** without asking. The user's notes are
  their own; add links from your notes to theirs instead.
- **Never edit a card.** `Карта —` and `Сфера —` files are rebuilt on every index.
- **No project specs here.** GDDs, ADRs and story files live in the project.
  The vault holds thinking, not specification.
- **No secrets.** No tokens, keys, passwords.

## Keeping it healthy

```bash
node tools/obsidian.mjs check
```

Reports broken links, duplicate titles, orphans, notes with no sphere, and notes
with more than six links. Run it after a batch of notes, not after every single
one.

How to act on what it says:

| Report | Action |
|---|---|
| broken link | the target was renamed: ask before recreating it, then fix the link |
| duplicate title | merge into one note, keep the better title |
| orphan | it has no links and nothing links to it: link it to a sphere or delete it |
| no sphere | ask the user which sphere it belongs to, then set it |
| more than 6 links | split the note, or move the list into the sphere card |

## What to record

| Signal | Note type |
|---|---|
| "а что если…", a mechanic worth trying | `идея` |
| a game idea worth developing | `концепт` |
| a sprint, a milestone, a checklist | `план` |
| a decision with reasoning | `документ` |
| an open question you cannot answer yet | `вопрос` |

Do not record: routine work logs, code, anything already in the project docs.
